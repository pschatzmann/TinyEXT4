TinyEXT4

[](LICENSE)

TinyEXT4 is a header-only Arduino library for the Linux ext2/ext3/ext4 file system without journaling. It is written for microcontrollers. It never needs a buffer for a full file system block: all metadata goes through a small cache of 512-byte sectors, so a mounted file system uses only a few KB of RAM. Read support covers ext2, ext3 and ext4 images as created by mkfs.ext4. Write support creates, changes and deletes files and directories on ext4 and keeps all checksums valid, so e2fsck and the Linux kernel accept the result.

Read Write
ext4 (extents, 64bit, flex_bg, metadata_csum, huge_file, dir_nlink, ...) yes yes, without writing the journal
ext3 / ext2 (block maps) yes no (mounted read-only)
htree (indexed) directories yes yes (the index is removed when an entry is added)
Symbolic links readlink() no
MBR and GPT partitions yes yes
Inline data, encryption, casefold, bigalloc, quota partly or read-only no (mounted read-only)

Why ext4 on a Microcontroller?

FAT is the default on microcontrollers because every PC can read it. When the data comes from Linux or goes to Linux, ext4 is often the better choice:

  • Exchange data with Linux devices. A Raspberry Pi, an embedded Linux board or a server can use the card without converting anything. The root partition of a Raspberry Pi OS card is ext4, so a microcontroller can read (or patch) configuration files on it directly.
  • No 4 GB file limit. FAT32 can't store files of 4 GB or more. Long audio or video recordings and large data logs fit in a single file on ext4.
  • Linux metadata. Owner, group, permission bits, timestamps and symbolic links survive the trip. Files written by the microcontroller get the owner and permissions you choose with setOwner() and setPermissions().
  • Checksums. With metadata_csum (the mkfs.ext4 default), every metadata block is checksummed, and TinyEXT4 keeps the checksums correct. Damaged metadata is detected by e2fsck and the kernel instead of going unnoticed.
  • Disk images on the network. Together with the NBD client of TinyNBD, a microcontroller can read and write an ext4 image that lives on a server, without any storage hardware of its own.
  • Small enough for small boards. Full ext4 implementations keep a cache of whole blocks (usually 4 KB each) and need tens of KB of RAM. TinyEXT4 runs with a 2 KB sector cache and works on boards like the SAMD21 with 32 KB of RAM. On an ESP32 or RP2350 the cache can be made larger and placed in PSRAM.
  • One header, no dependencies. It's plain C++ that also builds on the desktop, so you can develop and test your file handling with image files and e2fsck before you put it on the board.

When the card has to be read on Windows or macOS without extra drivers, stay with FAT (TinyFATFS). Also keep in mind that TinyEXT4 doesn't write a journal: after a power loss during a write, run e2fsck (or let Linux do it at mount time), just as you would fsck.vfat a FAT card.

Installation

For Arduino, you can download the library as a zip file and add it with Sketch → Include Library → Add .ZIP Library. Or you can git clone this project into the Arduino libraries folder, e.g. with

cd ~/Documents/Arduino/libraries
git clone https://github.com/pschatzmann/TinyEXT4.git

On the desktop: cmake -B build && cmake --build build && ctest --test-dir build.
